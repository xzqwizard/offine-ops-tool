# 项目说明

> 更新日期：2026-10-02（代码状态对齐 commit `670fbc0`）

## 1. 一句话定位

**OfflinePreOpsTool（离线部署运维工具）** 是一个运行在**有外网的办公机**上的 Windows 桌面应用：政务实施工程师用它定义"哪些服务器装哪些中间件、开放哪些端口"，工具跨架构拉取 Docker 镜像后，为**每台服务器生成一个自包含的离线部署包**。包通过 U 盘摆渡进政务内网，现场人员解压后执行 `bash deploy.sh` 即可一键完成 Docker 安装、镜像装载、服务编排、健康检查；日常运维使用包内的 `ops.sh` 与自动生成的运维文档。

## 2. 解决什么问题

政务/信创内网环境有四个硬约束，传统人工交付每次都在踩坑：

| 约束 | 人工交付的坑 | 本工具的对策 |
|---|---|---|
| 服务器无外网，不能 `docker pull` | 人工 pull + save，容易漏镜像、**拉错 CPU 架构** | 办公机侧跨架构拉取（crane `--platform`），构建时按服务器架构校验 |
| CPU 架构异构（x86/鲲鹏/飞腾/龙芯） | 拿错包到现场才发现 | 架构在方案中显式建模，构建前校验阻断（R3） |
| 交付物需可审计、防篡改 | 校验靠自觉 | SHA256SUMS（Linux）+ verify.bat（Windows）双侧校验、镜像 digest 记录进 manifest |
| 现场人员水平参差 | 步骤因人而异、文档与实际不符 | deploy.sh/ops.sh 一键化 + 文档由方案数据自动生成，与配置强一致 |

## 3. 两个使用阶段

```text
阶段一：外网办公机（本工具运行）
  新建方案（或复制/模板生成） → 录入服务器 → 编排中间件 → 画端口矩阵
    → 校验门禁 → 在线拉镜像（或本地导入） → 构建 → 每台服务器一个自包含包
                        │ U盘摆渡（附 SHA256 校验材料）
阶段二：政务内网服务器
  sha256sum -c 校验 → 解压 → bash precheck.sh → bash deploy.sh
    → 日常：bash ops.sh（菜单/子命令）+ docs/OPS-GUIDE.md
    → 升级：新版本增量包 → bash upgrade.sh（自动备份原编排，失败可回退）
```

## 4. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面框架 | **Tauri 2**（Rust 后端 + 系统 WebView） | 备选 Electron 已通过 `BackendAdapter` 接口层隔离，前端不依赖框架细节 |
| 前端 | **Vue 3 + TypeScript + Vite + Tailwind CSS 4 + Element Plus + Pinia + Vue Flow** | 用户明确指定，不用 React/AntD |
| 镜像引擎 | **crane**（go-containerregistry 官方 Windows 二进制，sidecar 方式调用） | skopeo 无 Windows 官方发行，故弃用；daemonless，办公机无需装 Docker |
| 外网 HTTP | 系统 **curl.exe**（Windows 10+ 原生） | 规避 Rust TLS 栈在 MinGW 工具链下的兼容问题；代理统一注入 |
| 模板引擎 | **minijinja** | 全部产物（脚本/compose/文档）由 `engine-templates/*.j2` 渲染生成 |
| 打包/校验 | tar + flate2 + sha2 + zip + rust_xlsxwriter | 纯 Rust 实现 |

## 5. 核心设计原则（新人必读）

1. **方案（Project）是唯一数据源**：服务器、中间件实例、端口规则、私有仓库全部存在一个 JSON 里。所有产物（compose、脚本、文档、xlsx）都是它的投影——改方案自动重渲染，不存在"文档过期"。
2. **模板外置**：`engine-templates/` 下的 Jinja 模板与代码解耦，现场定制（如某项目 compose 写法不同）只改模板不动程序。**模板必须保持 LF 行尾**（`.gitattributes` 已配置），否则生成的 bash 脚本带 `\r` 无法执行。
3. **构建前强校验**：13 类规则（R1-R13）作为门禁，错误阻断构建（详见功能清单 §校验体系）。
4. **自动保存**：所有表单增删改即时持久化（`store.commit` 串行链），无手动保存按钮——这是用户的明确要求。
5. **安全底线**：构建前字段白名单（防脚本/compose 注入）、删除类命令 canonicalize 路径校验、密码脱敏回显。

## 7. 开发环境注意（Windows + MinGW 工具链，踩过的坑）

本机 Rust 是 **windows-gnu（MinGW）** 工具链，与 Tauri 默认的 msvc 假设不同，有三处特殊配置（均已固化，但换机器需知晓）：

1. **crate-type 只能是 `["rlib"]`**：cdylib 在 MinGW 下触发 "export ordinal too large" 链接错误；
2. **rust-lld 链接**（`.cargo/config.toml`）：GNU ld 2.47 有产出口；lld 禁止重复资源，gcc specs 默认注入的 `default-manifest.o` 与 Tauri 清单冲突 → `build.rs` 注入自定义 specs（**换机器需重新生成**：`gcc -dumpspecs` 去掉 default-manifest 行）；
3. **build.rs 自动修复**：WebView2Loader.dll 落位到 deps/examples 子目录 + 全目标注入 common-controls v6 清单（缺清单的测试二进制会以 STATUS_ENTRYPOINT_NOT_FOUND 静默失败）；
4. **测试统一放 `src-tauri/tests/`**（集成测试目录，清单注入覆盖），不要写 lib 内 `#[cfg(test)]`；
5. **cargo 源已配 rsproxy 镜像**（crates.io 直连不稳时兜底）。

## 8. 常用命令

```bash
pnpm install          # 前端依赖
pnpm tauri dev        # 开发运行（GUI）

OfflinePreOpsTool.exe --build <方案id> --out build.log   # 退出码 0/1/2
```

## 9. 数据存放（便携式布局）

默认全部在**软件所在目录的 `data/`** 下（整个目录拷走即迁移，不写用户目录）：

| 路径 | 内容 |
|---|---|
| `data/settings.json` | 应用设置（存储根覆盖、代理、镜像源） |
| `data/projects/` | 方案文件（每方案一个目录一个 JSON） |
| `data/cache/` | 镜像缓存（docker-archives/ + bin/crane.exe） |
| `data/cache/docker-pkgs/` | Docker 离线安装包库 |
| `data/dist/` | 构建产物输出 |
| `data/logs/` | 应用日志 + audit.log 审计留痕 |

五个存储根均可在设置页单独改路径（目录选择器），但注意：**改路径只影响新写入，不自动搬数据**；备份/恢复（zip）已适配自定义路径。
