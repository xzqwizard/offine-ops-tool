# 使用说明

OfflinePreOpsTool 在联网 Windows 电脑上准备部署材料，生成供离线 Linux 主机使用的包。工具用于服务器、中间件和访问关系的配置与交付；业务应用数据的正确性需在目标环境核验。

## 安装和首次运行

从 [Releases](https://github.com/xzqwizard/offine-ops-tool/releases) 获取 Windows 10/11 x64 版本，核对附件的 SHA256。安装包包含 WebView2 离线安装程序；便携 ZIP 需完整解压到可写目录，且电脑已有 WebView2 Runtime。

启动后先查看设置中的存储位置。默认设置文件固定在 `<程序目录>/data/settings.json`；镜像和构建产物较大，可将五类存储根设到空间足够的位置。程序目录本身也需要可写，修改存储根不会移动设置文件。

在线查询或下载时，可按需要配置代理和镜像源。私有仓库凭据在方案内设置。密码的保存、迁移及导出边界见 [数据与隐私](数据与隐私.md)。

## 配置部署方案

1. 在方案页新建方案，或从模板、复制、导入开始。复制/导入会生成新的身份；复制服务器后需要重新填写 IP。
2. 填写每台服务器的 IPv4、架构、OS/版本、资源、Docker 版本、Docker 数据根和部署根。它们须与目标机一致。
3. 添加中间件实例。内置目录包括 MySQL、PostgreSQL、MongoDB、Redis、nginx、MinIO、RabbitMQ、Kafka、Elasticsearch、Nacos。也可使用自定义镜像和配置。
4. 配置实例参数、发布端口、持久化目录、UID:GID、依赖关系与就绪探针。需要备份的数据应设置明确的绑定目录；容器可写层和匿名卷不在通用冷备范围内。
5. 设置端口与来源规则，通过矩阵或拓扑核对访问关系。修改端口、协议或目标服务器时，工具同时调整关联规则。

表单会自动保存。离散操作在保存成功后更新页面，连续输入使用防抖保存；失败时保留输入并提示。构建前仍须完成校验，修改方案后原校验结果会失效。

## 准备镜像和安装材料

在线镜像能力使用 crane，在镜像库安装或更新引擎。联网电脑无需为镜像拉取安装 Docker。镜像可使用 tag 或明确的 sha256 digest；不同来源、平台和内容独立缓存。

已有离线镜像时，使用匹配引用与目标架构的 `docker save` tar。工具校验 config、层、标签及归档完整性；该校验不能证明远端仓库内容与本地 tar 相同。

Docker 材料库支持在线下载 amd64/arm64 官方静态包和 Compose 插件。其它架构及 RPM/DEB 需手工准备，原生包必须包含匹配目标 OS/版本/架构的 engine、cli、containerd 和必要依赖。本地 Compose 与 RPM/DEB 的声明文件及检查要求见 [材料准备指南](迁移与材料准备指南-2026-10-09.md)。

## 构建和摆渡

在构建页选择全量构建，确认材料完整并预留磁盘空间。构建检查失败会阻断交付，失败记录不能用作升级基线。任务可在其它页面查看进度、结果和日志。

每台服务器的目录或 tar.gz 包包含：

```text
<服务器包>/
├── manifest.json          # 构建身份、镜像及存储契约
├── deployment.env         # 部署身份
├── SHA256SUMS             # 包内文件校验和
├── docker-offline/        # 全量包的 Docker/Compose 安装材料
├── images/                # 本服务器的镜像
├── stack/                 # Compose 和持久化目录
├── scripts/               # 部署、预检、升级、防火墙和运维脚本
├── docs/                  # 运维指南和端口矩阵
└── README.md              # 该包的执行步骤
```

外层构建目录还包含索引、报告、脱敏方案快照等。打包模式提供外层校验文件及 `verify.bat`；目录模式使用各服务器自身的 `SHA256SUMS`。摆渡介质需支持大于 4 GB 的单文件。部署包含实际业务参数和密码，传递及保存时需要访问控制。

## Linux 首次部署

先按该服务器包的 `README.md` 解压并进入包目录，再执行：

```bash
sha256sum -c SHA256SUMS
sudo bash scripts/deploy.sh
sudo bash scripts/ops.sh status
```

脚本先检查 CPU、OS、资源、工具及内核条件，再安装或核对 Docker/Compose、加载镜像并检查服务。已有 Docker 不会被覆盖或重配；实际版本、数据根不匹配会拒绝继续。同一构建可重跑，不同构建应使用升级流程。

如需按方案限制发布端口来源，先核对端口矩阵，再显式执行：

```bash
sudo bash scripts/apply-firewall.sh --apply
```

仅支持 Docker IPv4 iptables 路径，并要求 DOCKER-USER 接入 FORWARD；也覆盖宿主 docker-proxy 的 INPUT 路径。原生 Docker nftables、IPv6及其它网络入口需要对应策略。部署后应从允许和拒绝来源分别测试，且核对数据库或业务数据；进程运行不等于业务正确。

日常启停、日志、冷备、恢复和回滚命令，以包内 `docs/OPS-GUIDE.md` 为准。

## 升级与恢复

生成增量包时选择与现场一致的成功构建作为基线。将增量包解压到独立目录，在增量包中执行：

```bash
sha256sum -c SHA256SUMS
sudo bash scripts/upgrade.sh --target <已部署目录> --dry-run
sudo bash scripts/upgrade.sh --target <已部署目录>
```

正式升级会冷备、更新编排和变化镜像、执行健康检查，成功后才更新部署身份；失败尝试自动回退。退出码 2 表示回退未完成，需保留提示的快照和恢复前目录并人工核查。

稳定实例 ID 决定数据目录，仅改实例名称不会改变目录。旧版按服务名存储、跨服务器移动、挂载或有状态版本不兼容时，需显式迁移，不能手工改 manifest 绕过门禁。具体步骤见 [迁移指南](迁移与材料准备指南-2026-10-09.md)。

## 数据备份与存储迁移

设置中的 ZIP 备份包含方案、设置和自定义目录，排除被识别的密码；不包含镜像、安装材料、构建产物或部署后的业务数据。恢复保留当前电脑的存储根，密码需重新填写。

普通保存存储设置只切换目录。“复制并切换”会冻结写入、复制到空目录、逐文件校验后发布设置，并保留原目录。它用于本机数据位置变更。跨电脑或 Windows 用户迁移请用导出/备份恢复流程；DPAPI 密文不能当作可移植凭据。

## 自动化构建和限制

已保存的方案可以由桌面程序的 CLI 入口构建：

```powershell
OfflinePreOpsTool.exe --build <方案ID> --out build.log
```

退出码：0 成功，1 构建失败，2 加载失败；结果另写入当前目录的 `build-cli-result.txt`。此入口仍依赖 Tauri 桌面运行环境，不是独立的 Linux 无界面构建服务。

签名和应用内自动更新尚未实现。配置能识别多种目标架构，不代表所有 OS、内核、安装材料及中间件已经认证；生产使用前应在对应环境验收。具体能力见 [功能清单](功能清单.md)，开发说明见 [项目结构](项目结构.md)。
