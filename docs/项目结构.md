# 项目结构与开发

本文描述当前源码的职责和开发入口。命令注册、字段和行为以代码为准；历史审查中的行号对应当时提交。

## 顶层目录

```text
OfflinePreOpsTool/
├── src/                         # Vue 3 / TypeScript 前端
├── src-tauri/
│   ├── src/                     # Rust 模型、IPC、存储、构建和任务模块
│   ├── tests/                   # 集成与脚本回归测试
│   ├── examples/                # 隔离验收材料渲染等辅助入口
│   ├── .cargo/                  # GNU 链接兼容配置和 Cargo 镜像源
│   ├── build.rs                 # Windows 构建兼容处理
│   ├── tauri.conf.json          # 桌面窗口、CSP 和打包配置
│   ├── tauri.release.conf.json  # Windows Release 安装包配置
│   └── capabilities/           # Tauri 权限
├── engine-templates/            # 编译内置的 Jinja 模板
├── catalog/preset.json          # 内置中间件目录
├── public/                      # 字体和图标等静态资源
├── scripts/                     # 图标、版本同步、发布打包与 Linux 验收
├── .github/workflows/           # Verify 和 Release
└── docs/                        # 用户、开发、隐私、发布和历史审查文档
```

模板通过 `include_str!` 编译进程序。修改 `engine-templates/` 或内置目录后需重新编译；修改安装目录外的模板不会热更新应用。

## 前端职责

| 入口 | 职责 |
|---|---|
| `router/index.ts`、`views/` | 工作台、方案管理/编辑、镜像库、安装材料库、设置 |
| `api/backend.ts` | 统一封装 Tauri `invoke`；与 Rust 命令签名和 `types/` 同步 |
| `stores/project.ts` | 草稿、串行保存、防抖、修订号和加载竞态处理 |
| `stores/tasks.ts`、`stores/buildTask.ts` | 全局任务和构建状态 |
| `components/project/` | 服务器、中间件、访问关系、校验和构建面板 |
| `components/layout/` | 标题栏、导航、状态栏、关闭时等待保存/任务 |
| `utils/projectDraft.ts` | 实例与关联规则的草稿修改 |
| `utils/validate.ts`、`imageReference.ts` | 前端字段校验、镜像引用解析 |
| `themes/`、`styles/` | 主题令牌及组件样式 |
| `tests/state.test.ts` | 保存竞态、任务隔离及字段/规则回归 |

离散操作先改草稿，保存成功后发布；连续输入走防抖保存。切方案、备份、构建和关窗前需等待保存。异步加载/校验应检查请求身份，避免旧响应覆盖新状态。注册 Tauri 事件时处理组件卸载早于 `listen()` 完成的情况，并及时注销监听。

## 主要数据流

```text
页面表单 → 方案草稿 → 串行保存 → 后端规范化/冻结/校验 → 本地 JSON
构建请求 → 冻结方案 → 后端门禁 → 镜像/材料验证 → 渲染 → 校验和 → 发布产物
联网请求 → net/crane + 代理 + 任务上下文 → 验证暂存文件 → 发布可信缓存
存储迁移 → 冻结写入 → 复制至空目录 → 逐文件校验 → 发布设置 → 保留旧根
```

构建先在临时位置准备文件，验证通过后发布；失败产物不作为升级基线。镜像运行身份使用 config SHA256，持久化目录使用实例 ID。增量升级同时比较方案、服务器和存储契约，详细约束见 [架构设计](方案设计.md)。

## 开发环境

需要 Node.js 22、pnpm 10、Rust 1.97.1 和 [Tauri 2 系统依赖](https://v2.tauri.app/start/prerequisites/)。Windows 推荐标准 MSVC 工具链；发布工作流以 Windows x64 MSVC 构建。Linux 的具体系统包见 [verify.yml](../.github/workflows/verify.yml)。

仓库保留 GNU 开发兼容配置：

- `src-tauri/.cargo/config.toml` 使用 rust-lld 和不稳定链接选项，并设置 rsproxy。MSVC 发布的检出副本移除此文件，使用标准 Cargo 默认配置。
- `build.rs` 的 GNU 路径注入 Common Controls v6 清单并处理测试/示例的 WebView2Loader DLL；`mingw-specs-nodm.txt` 去除 GCC 默认 manifest 注入。使用不同 MinGW 版本时需核对 specs 与实际工具链，不能把它视作通用 GCC 配置。
- Windows 脚本测试需要 Git for Windows 的真实 `usr/bin/bash.exe` 和 coreutils。辅助函数按 `PREOPS_BASH`、安装目录和 PATH 发现；可将 `PREOPS_BASH` 设置为实际 Bash 文件。`bin/bash.exe` 启动器会重排 PATH，WSL 启动器不适用于这些 Windows fixture。
- `.npmrc` 默认使用 npmmirror；受限网络可按环境配置镜像。需要官方源时，pnpm 命令使用 `--registry https://registry.npmjs.org`。构建镜像源是第三方联网端点。

## 验证入口

在仓库根执行：

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked
pnpm audit --prod --registry=https://registry.npmjs.org
pnpm tauri dev
```

集成测试按镜像、旧布局、任务、回归、渲染/脚本和 Excel 分组。脚本测试无法取得兼容 Bash 时应失败，不能静默跳过；模拟 Docker 的测试不替代真实部署验证。

Linux 隔离验收入口为 `scripts/acceptance-smoke.sh`，支持 `network`、`operations`、`identity`，会操作 Docker 容器及测试防火墙策略，使用隔离环境执行。CI 分别运行三个场景，代码检查和依赖审计单独执行。Windows Release 工作流执行检查、测试和打包；标签留空时仅试构建。

修改 IPC 时同步前后端类型；修改模板、材料或基线时执行相应回归和 Linux 场景；修改桌面交互时还需 Tauri 实机验证。提交示例和失败日志前检查地址、名称、路径与凭据，见 [数据与隐私](数据与隐私.md)。发版步骤见 [版本发布](版本发布.md)。
