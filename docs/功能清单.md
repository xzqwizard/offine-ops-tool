# 功能清单

> 更新日期：2026-10-02（对齐 commit `670fbc0`）。按用户操作路径分组，每项标注实现位置。
> 标 ★ 的是核心链路功能；标 🔒 的是有安全/正确性门禁的功能。

## 一、方案管理（方案的全生命周期）

### 1.1 新建 / 列表 / 删除
- 新建方案（名称必填 + 客户选填），列表展示服务器数/实例数/更新时间，删除需确认
- 实现：`commands.rs create_project/list_projects/delete_project` + `ProjectsView.vue`

### 1.2 ★ 方案复制
- 一键复制全部服务器/中间件/端口规则；**服务器 IP 自动清空待填**（新环境改 IP 即用）；实例与访问规则的服务器引用自动重映射（新 id）
- 实现：`commands.rs clone_project`

### 1.3 ★ 架构模板一键生成
- 两个内置模板：**经典四件套（双机）**——应用服务器（nginx+redis）+ 数据库服务器（mysql+minio）；**信创单机版**——单台 arm64 麒麟全套
- 自动生成服务器与实例骨架、端口按目录默认值、**密码全部自动生成强密码**（16 位四类字符）、IP 留空待填
- 实现：`utils/archTemplates.ts`（数据与生成逻辑）+ `ProjectsView.vue`

### 1.4 单方案导出 / 导入（.oppjson）
- 导出单个方案为 JSON 文件（含私有仓库配置，**含明文凭据**——UI 有保管提示）；导入生成新 id，重名自动加"（导入）"后缀
- 实现：`app_ops.rs export_project/import_project`

### 1.5 🔒 自动保存（无手动保存按钮）
- 全部表单增删改**即时持久化**；名称/客户/构建配置等连续输入走 600ms 防抖
- 保存请求**严格串行**（promise 链，防后端乱序落盘用旧快照覆盖新数据）；响应返回前若有新编辑则不回写内存（防输入被回滚）；切方案/删方案/备份前自动 flush 未落盘修改；保存失败界面保持"待保存"警示
- 实现：`stores/project.ts`（commit/scheduleSave/flushPending/saveChain）

### 1.6 方案编辑页（五页签）
- 服务器清单 / 中间件编排 / 端口矩阵 / 校验 / 构建，名称与客户行内编辑（防抖保存）
- 实现：`ProjectEditView.vue` + 五个子面板组件

## 二、服务器管理

### 2.1 服务器 CRUD
- 字段：名称/IP（**必填**，防火墙规则依赖）/主机名/CPU 架构/OS 族/系统版本/核数/内存/双盘容量/Docker 版本/数据目录/部署目录
- 校验：名称/主机名/IP 方案内唯一（R1）、IP 格式、Docker 版本必填
- 实现：`ServersPanel.vue`

### 2.2 CPU 架构选择（信创一等公民）
- amd64（Intel/AMD/海光/兆芯）、arm64（鲲鹏/飞腾）、loongarch64（龙芯）、mips64el/sw64（仅识别）
- 实现：`types/project.ts ARCH_OPTIONS`

### 2.3 系统版本预设选择
- 按 OS 族内置常见版本（麒麟 V10 SP1-SP3、UOS Server 20、openEuler 24.03 LTS 等），可搜索/可自定义输入；切换 OS 族自动带默认版本
- 实现：`types/project.ts OS_VERSION_OPTIONS`

### 2.4 ★ Docker 版本官方在线获取
- 选架构后自动从 `download.docker.com` 官方目录拉取版本列表（倒序、10 分钟缓存、异步不卡界面），默认最新，可过滤/手输；失败可重试
- loongarch64 等无官方包架构显示信创源提示，保留手输
- 实现：`docker_versions.rs`（解析 download.docker.com 目录页）+ `ServersPanel.vue`

### 2.5 删除级联
- 删服务器同时清理其上的中间件实例与相关访问规则（确认弹窗明示数量）

## 三、中间件编排

### 3.1 ★ 内置中间件目录（10 项）
- MySQL 8.0 / PostgreSQL 16 / MongoDB 7 / Redis 7 / Nginx / MinIO / RabbitMQ 3.13 / Kafka 3.7(KRaft) / Elasticsearch 8 / Nacos 2
- 每项含：默认镜像、推荐版本、支持架构、端口定义、参数表单描述（envHints）、数据卷、健康检查、最低内存、内核参数要求（ES 的 vm.max_map_count）
- 目录条目按实测修正过：redis 密码经 command requirepass 真正生效；ES8 默认关安全认证+180s 体检+uid 1000；kafka advertised 必填+uid 1001；nginx 卷挂 html 不遮蔽默认配置
- 实现：`catalog/preset.json` + `catalog.rs MiddlewareTemplate`

### 3.2 目录选择 + 手动输入镜像双模式
- 目录模式：选中间件 → 选版本（推荐置顶，可"获取在线版本列表"拉全量 tag）
- 手动模式：完整 registry/repo:tag 语法（可含 @sha256: digest），可"★ 存为我的中间件"（提取镜像/端口/参数存为目录条目，归入"我的中间件"分类，下次直接选）
- 实现：`InstanceFormDialog.vue` + `catalog.rs save_custom_template`

### 3.3 ★ 部署到服务器：新增模式多选批量
- 多选服务器一次部署 N 份（参数共享、逐机校验端口冲突/实例名唯一）；目录声明架构不兼容的服务器自动跳过并提示
- 编辑模式单台，可换目标服务器
- 实现：`InstanceFormDialog.vue`（formServerIds 多选集合为唯一数据源）+ `MiddlewarePanel.vue saveInstances`

### 3.4 🔒 实例校验
- 实例名（compose 服务名规范）、镜像引用字符白名单、同机宿主端口冲突（R2）、实例名同机唯一、必填参数（R7）、本地 tar 路径存在性
- 实现：`MiddlewarePanel.vue validateInstance` + 构建前 `validateProject`

### 3.5 ★ 镜像在线检查（架构矩阵）
- "在线检查镜像"按钮：实时查询该引用的**架构支持矩阵**（逐 tag 查 manifest）
- 匹配规则：忽略 variant（linux/arm64:v8 属于 arm64）、OCI 架构别名映射（loong64↔loongarch64、amd64↔x86_64）、过滤 attestation 的 unknown 平台
- 明确不支持时**保存阻断**；检查结果绑定检查时的引用（改 tag 自动作废，防串档）
- 实现：`images.rs inspect_image` + `InstanceFormDialog.vue archMatches`

### 3.6 digest 锁定
- 在线检查成功且针对当前引用时，digest 自动写入实例（编辑保留原值，引用变更需重新检查）
- 构建 manifest 记录每镜像 digest（审计/防替换）

## 五、校验体系（构建前强制门禁）

| 编号 | 规则 | 级别 |
|---|---|---|
| R1 | 服务器名称/主机名/IP 重复 | 阻断 |
| R2 | 同机宿主端口冲突（含实例内部） | 阻断 |
| R3 | 镜像架构与服务器架构不兼容（目录声明） | 阻断 |
| R4 | 中间件最低内存合计 vs 服务器内存 | 阻断/警告 |
| R6 | latest 标签 | 警告 |
| R7 | 目录必填参数缺失 | 阻断 |
| R9 | 访问规则目标端口未暴露 | 阻断 |
| R10 | Docker 安装包/插件缺失（构建面板预检） | 阻断 |
| R12 | loongarch64 信创提示 | 提示 |
| I-xxx | 未填本地 tar 的在线拉取提示、结构完整性 | 提示 |

- 校验结果按 `revision` 修订号判过期（任何修改后提示重新校验）；构建面板入口也做 R10 预检
- 实现：`utils/validate.ts` + `BuildPanel.vue checkDockerPkgs`

## 六、镜像库（拉取与缓存）

### 6.1 ★ crane 引擎管理
- 引擎未装时从 go-containerregistry 官方 GitHub Release 下载（**SHA256 校验** + 原子替换 + 代理联动 + 进度日志）；支持检查更新
- 实现：`engine.rs`

### 6.2 ★ 手动拉取（跨架构）
- 输入引用 + 选目标架构；docker.io 引用按镜像源列表顺序回退（daocloud/1ms 内置，可配置）；**拉取后改写 tar 内 RepoTags 为原始引用**（否则 load 后与 compose 对不上）
- **进度条**：manifest 层总量估算 + 临时文件增长监视 → 百分比/速度/已下载量
- 实现：`images.rs pull_image` + `ImagesView.vue`

### 6.3 缓存体系
- 缓存键 = registry+repo+tag/digest+平台（**不同版本绝不共享缓存**）；命中直接复用（多服务器同镜像不重复下载）；并发拉取用唯一临时文件名 + rename 冲突防护；失败清理临时文件
- 缓存列表：引用/平台/大小/拉取时间/**被方案引用**（归一化匹配）/删除
- **一键清理未引用**：部分失败汇总语义
- 实现：`images.rs` + `app_ops.rs analyze_cache_usage/purge_unref_cache`

### 6.4 网络代理（设置页）
- HTTP/SOCKS5（socks5h，DNS 走代理）、认证账号密码、no_proxy 直连名单；对**所有外网访问统一生效**（curl -x / 子进程环境变量）；密码脱敏回显 + URL 百分号编码
- **测试连通性**：弹窗逐目标实时进度（代理通道→Docker Hub 认证→Registry→国内源），直接用界面当前配置（无需先保存），诊断提示文案
- 实现：`net.rs` + `SettingsView.vue`

### 6.5 项目级私有仓库
- 方案编辑页折叠配置（地址/用户名/密码）；启用后镜像拉取/版本查询/架构检查**优先走私有 Harbor**（crane auth login，**密码走 stdin** 不上命令行；登录按 host 记忆；认证失败不阻断回退公共源）
- 实现：`models.rs RegistryConfig` + `images.rs registry_login`

### 6.6 本地镜像导入
- 实例表单填本地 `docker save` tar 绝对路径；构建时校验 tar 内 RepoTags 与实例引用一致（不一致警告——防现场 load 后 compose 找不到镜像）
- 实现：`builder.rs read_tar_repo_tags`

## 八、构建中心

### 8.1 ★ 构建管线（每台服务器一个自包含包）
```text
汇总 → 校验门禁（R1-R13 + R10 预检 + 字段白名单） → 镜像解析三级（本地tar→缓存→在线拉取）
  → 渲染（compose/脚本/文档） → compose YAML 语法校验（构建期拦截非法产物）
  → Docker 材料匹配 → manifest.json + SHA256SUMS → 方案快照
  → tar.gz 打包（镜像 store 模式不二次压缩） → SHA256SUMS.all + verify.bat → 构建报告
```
- 全程异步（不卡界面）+ 逐事件进度日志；构建前磁盘空间预检（不足二次确认）
- 实现：`builder.rs build_inner`

### 8.2 产物结构（每服务器）
```text
<服务器名>_<架构>/            # 目录名保留中文（sanitize 保留 Unicode 字母数字）
├── manifest.json             # 构建/镜像(含digest)/端口摘要
├── SHA256SUMS                # 包内全文件校验
├── README.md                 # 部署指引（含摆渡校验/U盘格式提示）
├── docker-offline/           # install-docker.sh + packages/（rpm|deb|tgz + compose 插件）
├── images/                   # 镜像 tar（docker load 兼容，RepoTags=原始引用）
├── stack/docker-compose.yml  # 编排（数据卷 ./data/<服务名>）
├── scripts/                  # precheck.sh deploy.sh ops.sh apply-firewall.sh
├── docs/OPS-GUIDE.md         # 运维手册（错误码表/巡检/备份/故障排查/安全红线）
├── docs/PORT-MATRIX.md       # 本机端口矩阵（含部署顺序建议）
└── logs/
```
- 产物根另生成：`build-manifest.json`（机器可读索引）、`project-snapshot.json`（方案快照）、`SHA256SUMS.all` + `verify.bat`（Windows 侧摆渡校验，chcp 65001 支持中文包名）、`build-report.md`、全网 `PORT-MATRIX.md`（含**建议部署顺序**拓扑推导）

### 8.3 🔒 渲染安全
- 字段白名单（实例名/镜像引用/参数值/服务器字段拒绝引号换行反引号）；env 值 YAML 转义（`$`→`$$` 防插值截断、单引号安全）；compose 项目名合规化（compose_name）；渲染产物强制过 YAML 语法校验
- 实现：`builder.rs validate_render_fields/shell_quote/compose_name`

## 十二、现场脚本（产物内，全部由模板生成）

### 12.1 precheck.sh（环境预检，可独立执行）
- root/架构匹配（uname vs 包架构）/OS/内存/磁盘/端口占用/内核参数（vm.max_map_count 等）/已装 Docker 版本/防火墙状态；`--strict` 模式供自动化；输出报告
- 错误码 **D1**

### 12.2 ★ deploy.sh（一键部署，幂等可重跑）
- 流程：预检 → 装离线 Docker（已装版本一致跳过、不一致不覆盖；含 compose 插件）→ daemon.json（data-root/日志轮转）→ load 镜像 → compose 校验 → 数据目录按 dataUser 预建 chown → up -d → 健康检查（exec/tcp，超时计入失败并 dump 日志）→ 报告
- `--dry-run` 全程演练（无 Docker 机器也能走完）；`--yes`
- **错误码 D1-D4**（与 OPS-GUIDE 对照表联动）
- compose 生成细节：项目名合规化、镜像/端口/命令全引号、env 单引号+`$$` 转义、depends_on 支持、空 ports 过滤

### 12.3 ops.sh（日常运维，菜单+子命令双形态）
```text
status          服务总览（STATE/HEALTH/PORTS，含容器不存在兜底）
start|stop|restart <svc|all>
```
