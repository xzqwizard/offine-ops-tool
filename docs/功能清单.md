# 功能清单

> 更新日期：2026-10-09。对应本次审查后的工作区修复；验收证据和未覆盖环境见《代码审查与业务闭环核查-2026-10-09》。

## 方案与服务器

- 新建、复制、导入、导出、删除、架构模板生成和构建快照恢复。复制/导入生成新身份并重映射关联；复制服务器 IP 留空待填。
- 离散表单修改先在草稿保存，成功才发布到页面；失败保留原方案及表单输入。连续输入防抖保存，请求串行，返回时保留在途新编辑。切方案、备份和关窗前等待保存。
- 后端保存返回冻结模板和规范字段后的真实对象，页面、磁盘和构建使用同一份定义。
- 本机仓库、代理和中间件秘密参数使用 Windows DPAPI；普通参数不因 `dpapi:` 前缀被误解密。便携方案、ZIP 数据备份和构建快照脱敏，恢复后重新填写密码。现场 Compose 仍包含部署密码。
- 服务器字段含 IPv4、架构、位数、OS/版本、资源、Docker 版本、数据根和部署根；在线版本列表支持缓存与过期响应过滤。离线执行使用 Docker 服务端版本核对。
- 支持 amd64、arm64、loongarch64、mips64el、sw64 的配置识别；材料和镜像能否部署取决于实际供应及目标验证。平台别名和 arm64 variant 在前后端统一匹配。

实现：`stores/project.ts`、`commands.rs`、`store.rs`、`credentials.rs`、`ServersPanel.vue`。

## 中间件与访问关系

- 预置 MySQL、PostgreSQL、MongoDB、Redis、nginx、MinIO、RabbitMQ、Kafka、Elasticsearch、Nacos 共 10 项；参数、命令、挂载、属主、探针、内存及内核要求随模板冻结。
- 目录选择与手动镜像两种输入；新增可批量部署，编辑可改名/改服务器。架构不支持有明确反馈，本地 tar 以构建期实际内容校验为准。
- 自定义配置可设置容器持久化目录、UID:GID、JSON 命令数组、none/TCP/exec 就绪探针及超时；exec 可调用镜像内 HTTP 工具。可直接随实例冻结，也可保存为“我的中间件”。批量创建时实例配置分别冻结，编辑已有共享配置时隔离当前实例，避免连带修改其它实例。无探针只检查连续稳定运行，不宣称业务可用。
- 修改实例的发布端口、协议和服务器时，关联规则随修改迁移；移除退役暴露规则，保留其它实例仍使用的规则。全部修改随同一草稿保存。
- 矩阵按端口及协议放行；拓扑使用独立 Handle，边保留 TCP/UDP。校验无问题也显示成功，方案变化使旧校验失效。

实现：`InstanceFormDialog.vue`、`MiddlewarePanel.vue`、`projectDraft.ts`、`TopologyGraph.vue`、`validation.rs`、`render_context.rs`。

## 镜像与引擎

- crane 为跨平台拉取引擎，可安装、检查更新、强制重装；记录实际执行版本、下载来源、SHA256 和体积。未校验通过的下载不会覆盖可用版本。
- 引用解析支持仓库端口、tag、sha256 digest；查询版本和平台不会阻塞主线程。私有仓库使用任务独立认证配置，认证失败不会静默转为公共仓库内容；密码通过 stdin 登录。
- 缓存按来源身份、引用、平台和锁定 digest 隔离；完整可信缓存优先，不为复用缓存强制联网。手动刷新需要清理对应缓存后重拉。
- 本地 `docker save` tar、缓存及在线内容统一验证 manifest、平台、层、config 和归档完整性。引用不匹配/层缺失/校验失败阻断构建。选择本地 tar 清除隐藏在线 digest；显式 `@digest` 需先改为归档实际 repo:tag。
- 交付 tar 的 RepoTags 和 Compose 使用 `offline.local/image:<config SHA256>`，manifest 同时保留来源引用、内容 SHA256 和运行引用。相同来源 tag 的不同内容可同机并存。
- 构建日志记录镜像验证、复制改写和打包耗时，便于定位大镜像瓶颈。

实现：`engine.rs`、`images.rs`、`image_archive.rs`、`builder.rs`。

## Docker/Compose 安装材料

- 在线下载 amd64/arm64 官方静态 Docker、Compose 插件；其它架构手工准备。静态归档校验必需二进制的完整 ELF 与平台、gzip 流完整性。
- RPM/DEB 需逐文件 `.pkg.json` 声明目标 OS/版本、架构、engineVersion、角色和 SHA256；解析包内真实名称、版本、架构并与声明比对。engine、cli、containerd 必须齐全，原生依赖需对应目标 OS。文件名不是唯一证据。
- Compose 插件需 `.compose.json` 记录 arch/version/source/sizeBytes/sha256。在线下载核对发布校验和；本地导入和构建都核对完整 ELF、大小及 SHA256。旧无元数据插件需重新导入/下载。
- 导入文件和元数据先 staging，再一同发布；失败还原旧组。构建只复制已验证、声明的文件集合，未声明附加文件和同名异内容文件会被拒绝；产物记录 `materials.json`。
- 材料库显示 Compose 版本、来源、异常及材料来源。格式/身份校验不等同于在所有发行版安装认证。

实现：`docker_pkgs.rs`、`DockerPkgsView.vue`。声明示例见《迁移与材料准备指南-2026-10-09》。

## 构建、基线与现场运维

- 全量构建：统一校验 → 镜像解析及不可变运行身份 → 安装材料门禁 → Compose/脚本/文档 → manifest、SHA256、脱敏快照 → 目录或 tar.gz。失败构建不能作为基线。
- 每服务器含 `manifest.json`、`deployment.env`、`SHA256SUMS`、`docker-offline/`、`images/`、`stack/`、`scripts/`、`docs/`；外层含构建索引/报告/方案快照/端口矩阵。tar.gz 模式另有包校验和及 `verify.bat`。
- `manifest` schema 2、storageSchemaVersion 1，记录实例稳定 ID、服务器、数据目录、容器挂载、版本兼容性和运行引用。数据目录为 `stack/data/<实例ID>/`，改名不改变存储。
- 增量包绑定当前完整基线，仅带变化镜像；服务器集合/OS/架构/IP/Docker/路径变化阻断，跨服务器移动、挂载变化和保守有状态版本变化需显式迁移。旧无稳定存储契约的基线拒绝直接升级。
- `deploy.sh` 先 `precheck.sh --before-install` 检查 CPU、OS/版本、工具、内存、磁盘和内核，再安装/核对 Docker，最后检查实际 daemon、数据根和端口。已有 Docker 不覆盖或重配；同构建可重跑，不同构建需升级。
- `upgrade.sh --target <部署目录> [--dry-run]` 校验包、身份、基线和编排；正式执行加锁、冷备、加载镜像、切编排、启动及健康检查，成功才发布身份。失败自动恢复，恢复失败明确退出 2。
- `ops.sh` 提供 status、logs、start/stop/restart、exec、backup、restore/rollback、prune-backups、report。备份暂停本方案服务，保存绑定目录和实际容器 `.Image`；恢复核对实际镜像与健康。恢复前目录保留供人工检查。
- `apply-firewall.sh --apply [--no-persist]` 需要 Docker IPv4 iptables DOCKER-USER 已接入 FORWARD，同时覆盖宿主 docker-proxy INPUT 路径；仅限制配置地址的发布端口，保留本机访问。原生 Docker nftables 不支持，IPv6/其它地址/容器直连策略需另配。持久化通过本方案 systemd 单元，升级/恢复重应用。
- Shell 健康探针有截止时间；INT/TERM 返回 130/143，普通失败非零，回退未完成返回 2。查看日志之外还需核对 SQL/业务数据。

实现：`builder.rs`、`baseline.rs`、`compose.rs`、全部 `engine-templates`。

## 全局任务、设置与迁移

- 构建、镜像拉取、引擎和材料下载/导入、网络测试、存储迁移使用全局任务 ID 和参数快照，跨页可查看阶段、日志、结果及错误；阻断重复提交，最多同时 2 项、保留最近 50 项，清理历史时保留全部在途任务。
- 取消能覆盖排队和在途任务；循环检查取消，子进程有截止时间并终止所属进程树，临时文件清理。取消晚到不会把已完成任务误标取消。关窗可等待或取消任务后等待结束，等待期间阻断新任务，取消关闭后恢复操作。
- 网络测试以规范化完整 URL 为键；界面目标、事件和最终结果使用同一清单。单目标失败仍有明确结果。
- 五个存储根可独立设置，普通保存只切换位置。另提供“复制并切换”：冻结写入、估算空间、复制到空目录、逐文件校验、最后发布设置；失败保留源数据并清理本次未发布副本，成功保留旧目录可回退。设置保存后回读规范值，切换方案根清除旧加载状态。
- ZIP 工具数据备份包含脱敏方案、目录和设置，不含镜像、安装包、产物；恢复保留本机根路径并重新加载。%APPDATA% 旧布局兼容迁移仍是只复制不覆盖。
- 关键操作有本地审计；前端启用 CSP，允许应用资源/IPC 和现有内联样式。

实现：`stores/tasks.ts`、`tasks.rs`、`storage_migration.rs`、`SettingsView.vue`、`TitleBar.vue`、`AppStatusBar.vue`、`net.rs`。

## 验证与边界

`pnpm test/build/audit --prod`、Rust fmt/clippy/test、Linux 真实 Docker 冒烟为验证入口。CI 将 network、operations、identity 拆为独立场景，一个失败不跳过其它场景。

- 签名尚未实现，启用签名会拒绝构建；SHA256 仅提供完整性校验。
- 自定义无绑定数据卷的可写层/匿名卷不在冷备中；须按业务配置卷或独立备份。
- 新装 Docker、RPM/DEB 依赖、其它中间件及国产 OS/CPU、生产网络仍需对应目标专项验收。本次真实结果以审查报告修复验收章节为准。
- 旧部署不会自动迁移到稳定实例目录；请按迁移指南冷停、复制并核查真实数据。
