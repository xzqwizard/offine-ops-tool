# 数据与隐私

本说明介绍应用如何保存和使用数据，以及向公开仓库提交材料前需要检查的内容。密码脱敏只覆盖程序识别的字段，不能当作对整个文件的匿名化处理。

## 本地保存的信息

默认布局位于程序旁的 `data/`：

| 位置 | 内容 |
|---|---|
| `settings.json` | 存储根、代理、镜像源和目录源等设置 |
| `projects/` | 项目/客户名称、服务器地址、资源、实例、端口规则和仓库配置 |
| `custom-catalog.json` | 自定义中间件模板及普通默认参数 |
| `cache/`、`cache/docker-pkgs/` | crane、镜像、安装材料及来源/校验元数据 |
| `dist/` | 部署包、构建清单、快照、报告和端口矩阵 |
| `logs/` | 运行与操作审计记录 |

五类数据根可被设置覆盖，设置文件仍在程序旁。开发运行的数据位于测试/开发程序所在目录下，不会自动成为源码。请确认自定义位置的权限和磁盘空间；日志、缓存和部署包也可能暴露环境信息。

## 密码保护与导出边界

Windows 使用 DPAPI 保存仓库/代理密码及被识别的中间件秘密参数。识别来自目录字段的 `secret` 标记和程序的秘密键规则。自定义模板须正确标识秘密参数；不要把真实 token 或密码写入普通参数、模板说明、命令或 URL。

DPAPI 绑定 Windows 用户，不能据此将密文复制到另一机器或用户并继续解密，也不能保护同一用户下正在运行的恶意程序。方案/设置其它字段不是加密保存；程序运行和生成部署配置时仍需使用实际密码。

| 操作或文件 | 自动排除的内容 | 仍需检查的内容 |
|---|---|---|
| 单方案导出、构建快照 | 仓库密码、被识别的秘密参数及冻结模板中的秘密默认值 | 项目/客户名称、IP、域名、仓库用户名、镜像引用、本地/部署路径、普通自定义字段 |
| 应用 ZIP 备份 | 上述方案秘密、代理密码、自定义目录中的秘密默认值 | 代理地址/用户名、存储根、目录源、方案和普通模板字段 |
| 现场部署包 | 不提供整包脱敏 | Compose 含部署密码，文档/manifest 含网络、镜像与目录信息 |
| 业务冷备、运维日志/报告 | 不提供业务数据匿名化保证 | 数据库/文件内容、容器日志、用户名、地址、目录及业务标识 |

备份恢复后需重新填写密码，恢复保留当前机器的存储根。ZIP 应用备份不包含镜像、安装材料、部署产物或目标机业务数据。跨机器迁移请使用备份或导出并重新配置凭据；本机“复制并切换”存储根不解决跨用户 DPAPI 问题。

## 联网行为

应用按相关操作访问 Docker 镜像仓库、配置的镜像源/代理、Docker 官方下载站、GitHub 的 crane/Compose 发布地址和配置的 HTTPS 目录源。网络测试会访问界面显示的目标，包括 Docker Hub 认证/仓库端点；设置代理时可包含公共连通性目标。

镜像查询/拉取会发送镜像引用和目标平台，私有仓库操作使用相应认证；下载服务器和代理能看到请求及网络来源。当前源码未实现自动上传部署方案、业务数据或使用分析遥测的功能；用户选择的下载、目录及镜像服务仍会收到对应请求。开发安装依赖还会访问 `.npmrc` 与 Cargo 配置指定的第三方镜像源。

离线目标机按包内脚本操作本地 Docker 和文件，不依赖应用把现场业务数据上传到公共仓库。业务镜像本身的网络行为由其配置及发布方决定。

## 向公开仓库提交材料

提交 Issue、讨论、截图、日志或复现文件前：

1. 使用新建的示例方案和虚构名称，地址优先使用文档示例网段、`example.com` 或占位符，保持关联关系便于复现。
2. 检查完整内容，替换真实客户名称、IP/域名、仓库/代理用户名、本地用户目录和部署路径。
3. 删除密码、token、Cookie、Authorization、私钥及 DPAPI 密文。不要直接上传 settings、原始方案、部署包或业务备份。
4. 日志只保留复现所需片段，检查 URL 参数、子进程输出、数据库结果及截图背景。
5. 保留应用版本、目标 OS/架构、错误步骤及经过脱敏的必要配置；脱敏可能影响复现时注明替换的字段。

仓库 `.gitignore` 排除默认运行数据、构建产物、日志、常见本地环境文件和私钥容器。它不会阻止已跟踪文件中的内容泄露，也无法保护仓库外的自定义数据根。维护者提交前仍需检查暂存差异，示例中只使用占位值。

## Git 历史与凭据泄露

Git 提交也会公开作者和提交者的姓名、邮箱。若不希望公开个人或工作邮箱，在 GitHub 的邮箱设置中查看自己的 noreply 地址，并在提交前设置此仓库的本地身份：

```bash
git config --local user.name "<公开 GitHub 用户名>"
git config --local user.email "<GitHub 提供的 noreply 邮箱>"
```

修改配置只影响后续提交，不会修改已有提交的作者或提交者信息。推送前还应核对新提交的元数据；以上设置不修改全局 Git 身份。

修改或删除最新文件不会移除旧提交、fork、缓存及已下载副本中的内容。若误公开真实密码、token 或私钥，应先撤销或轮换，再清理相关引用；历史重写需要单独协调，不能替代轮换。

历史审查报告的代码链接固定在其基线提交，便于核查当时结论。报告中的旧缺陷和测试结果应结合后续修复记录阅读，不能直接视为当前版本状态。
