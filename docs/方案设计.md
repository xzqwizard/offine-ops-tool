# 架构设计

本文描述当前实现。早期方案中的 Electron、skopeo、GPG 签名等设想不构成现有能力；当前功能与限制见 [功能清单](功能清单.md)。

## 使用模型与技术栈

工具分为联网准备和离线执行两个阶段。Windows 桌面应用保存方案、准备镜像与安装材料、生成每台服务器的包；Linux 目标机依据包内清单执行部署和运维。目标机不需要运行桌面应用。

| 层 | 当前实现 |
|---|---|
| 界面 | Vue 3、TypeScript、Vite、Element Plus、Tailwind CSS、Pinia、Vue Flow |
| 桌面与后端 | Tauri 2、Rust，前端统一由 `api/backend.ts` 调用 IPC |
| 镜像 | crane，无 Docker daemon 的联网查询/拉取；支持本地 docker-save tar |
| 网络 | curl 与统一代理配置、任务截止时间 |
| 渲染 | minijinja，模板及内置目录编译进程序 |
| 文件与存储 | JSON、tar/gzip、ZIP、SHA256、Excel 导出，Windows DPAPI 凭据保护 |

当前仅实现 Tauri 后端。crane 由应用下载到本地缓存，未实现 skopeo 或本机 Docker 拉取模式。

## 方案与模板

`Project` 是方案的主要数据源，包含服务器、中间件实例、端口/来源规则、私有仓库配置、构建选项和冻结模板。服务器、实例及方案具有稳定 ID；名称用于展示，不能作为存储身份。

中间件目录由内置、自定义及远程导入内容组成。实例使用的模板在保存和构建时冻结，减少目录后来变化对既有方案的影响。模板描述镜像、环境参数、端口、挂载、运行命令、UID:GID、健康探针及资源/内核要求。自定义秘密参数需正确标识为 secret。

表单采用草稿与串行保存，后端返回实际规范化对象。前端校验用于即时反馈，保存/导入/构建仍由后端检查，防止绕过界面产生非法方案。修改方案后旧校验失效，异步结果须绑定方案和请求身份。

数据结构见 [models.rs](../src-tauri/src/models.rs)、[catalog.rs](../src-tauri/src/catalog.rs)，校验见 [validation.rs](../src-tauri/src/validation.rs)。

## 本地存储和凭据

设置文件固定在 `<程序目录>/data/settings.json`。方案、镜像缓存、Docker 材料、构建产物和日志五类根默认位于同一 data 目录，可分别覆盖。旧用户目录布局在首次访问时进行只复制、不覆盖的兼容合并。

Windows 保存时对仓库/代理密码及被识别的秘密参数使用 DPAPI，加密内容绑定当前 Windows 用户。方案导出、备份和快照移除被识别的秘密；部署 Compose 仍需实际业务密码。非 Windows 不提供真实凭据保存能力。整个数据目录不是加密保险箱，名称、地址和普通参数仍是明文。

普通保存只切换存储根。“复制并切换”冻结写入，检查目标/空间/目录关系，在空目录中复制并校验，最后发布设置；原根保留。ZIP 备份只包含脱敏方案、设置、自定义目录，恢复使用当前机器存储根和事务替换。更多边界见 [数据与隐私](数据与隐私.md)。

## 镜像身份与缓存

镜像引用支持仓库端口、tag 和 sha256 digest，按来源、引用、平台与锁定 digest 区分缓存。私有仓库使用任务独立认证配置，密码经 stdin 登录，认证失败不会静默切到公共内容。完整可信缓存可离线复用。

本地 tar、缓存与在线材料统一验证 Docker manifest、config、层、RepoTags 和平台。构建使用 `offline.local/image:<config SHA256>` 作为运行引用；manifest 保留来源引用和内容身份，避免不同包的同名 tag 互相覆盖。该身份避免 tag 歧义，不能代替发布方签名或可信来源核验。

冷备保存实际容器 `.Image` 对应的镜像，而非重新解析可变 tag。恢复后核对运行镜像与健康状态，真实业务数据仍须专项检查。实现见 [image_archive.rs](../src-tauri/src/image_archive.rs)、[images.rs](../src-tauri/src/images.rs)。

## 安装材料门禁

官方静态 Docker 和 Compose 在线材料提供 amd64/arm64；其它架构需手工导入。静态材料验证归档流、必需文件及完整 ELF 的平台信息。Compose 使用版本、来源、大小、SHA256 声明，与二进制一起发布。

RPM/DEB 按文件声明 OS/版本、架构、兼容引擎版本和角色，并核对包内元数据。engine、cli、containerd 必须齐备，其它依赖归为 dependency。构建只复制经过验证的声明集合，记录 `materials.json`；未声明附加文件和身份不匹配会阻断。

格式与身份校验无法证明发行版依赖闭包、内核兼容或实际安装成功，必须在对应环境验收。声明格式见 [材料准备指南](迁移与材料准备指南-2026-10-09.md)，实现见 [docker_pkgs.rs](../src-tauri/src/docker_pkgs.rs)。

## 构建和产物

```text
冻结方案与目录
  → 后端字段/引用/关系门禁
  → 安装材料和镜像解析、验证
  → 每服务器渲染 Compose、脚本及文档
  → manifest、部署身份、SHA256 和脱敏快照
  → 目录或 tar.gz
  → 验证成功后发布构建结果
```

完整包按服务器自包含，包含 Docker 材料、镜像、编排、脚本和说明。打包模式另有外层校验材料，目录模式由各服务器的 `SHA256SUMS` 校验。构建使用临时位置，失败不发布可用基线。模板与代码一同编译，修改模板后需重新构建应用。

SHA256 只能检测文件内容变化，无法认证发布者；包签名尚未实现，启用签名会明确拒绝构建。实现见 [builder.rs](../src-tauri/src/builder.rs) 和 [engine-templates](../engine-templates/)。

## 稳定存储和增量升级

当前服务器 manifest 使用 schema 2、storageSchemaVersion 1，记录方案/服务器/实例身份、运行引用、数据目录及容器挂载契约。持久化目录为 `stack/data/<实例ID>/`，仅改名不改变数据位置。

增量包绑定成功的完整基线，只带变化镜像和新的编排/脚本/文档。服务器集合、OS、架构、IP、Docker 版本或路径变化阻断直接升级；跨服务器移动、挂载变化和保守的有状态版本变化需显式迁移。旧版缺失稳定存储契约的基线不能通过修改版本号获得兼容。

升级先校验包、身份、基线和编排，再锁定目标、冷备、载入镜像、切换编排和检查健康，成功才发布身份。失败尝试恢复原配置、镜像和绑定目录；回退未完成返回 2 并保留恢复材料。实现见 [baseline.rs](../src-tauri/src/baseline.rs) 与 `upgrade.sh.j2`。

## Linux 运维与网络

`deploy.sh` 在修改宿主前预检环境，已有 Docker 不覆盖或重配，同一构建可重跑。`ops.sh` 提供状态、日志、启停、exec、冷备、恢复/回滚、备份清理和报告；没有独立的 `rollback.sh` 或 `doctor` 子命令。

通用冷备暂停本方案服务，保存绑定目录和实际镜像，随后恢复服务；不覆盖容器可写层、匿名卷或任意外置数据。恢复检查镜像和健康并保留恢复前目录。数据库一致性与业务可用性须用对应 SQL 或业务校验确认。

来源策略只限制方案中的 Docker IPv4 发布端口，使用 iptables DOCKER-USER 和宿主 INPUT 以覆盖转发/docker-proxy。应用策略需显式执行，持久化由方案 systemd 单元维护。原生 Docker nftables 明确拒绝；IPv6、其它地址和容器直连需另配。CI 只证明其覆盖场景的结果。

## 任务与验证

构建、拉取、下载、导入、网络测试和迁移使用任务 ID，前端跨页追踪、去重、取消。子进程有截止时间，取消清理临时材料并终止所属进程树；已完成的有效结果不会被晚到取消误删。关闭窗口时等待保存和任务结束。

前端状态回归、Rust 格式/Clippy/集成测试、依赖审计及 Linux 真实 Docker 场景在 Verify 工作流中执行。Windows Release 另验证 MSVC 构建、测试和打包。历史报告保留当时的测试结果，不代表当前版本或全部现场环境。

尚需按目标验证其它中间件、OS/CPU、全新 Docker/RPM/DEB 安装、生产防火墙及桌面交互。应用内自动更新和代码/部署包签名未实现。开发入口见 [项目结构](项目结构.md)，发布入口见 [版本发布](版本发布.md)。
